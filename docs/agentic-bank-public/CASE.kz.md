# Halyk AI Challenge

**Құрылымдалмаған қаржылық құжаттарды талдап, корпоративтік несие шарттарындағы ковенанттардың сақталуын дәл анықтайтын AI агентін әзірлеңіз.**

---

## 1. Тапсырма

Әрбір қарыз алушының **несие шартында** бірнеше қаржылық ковенант көрсетілген. Бұл — банктер корпоративтік несие шарттарында белгілейтін қаржылық талаптар.

**Әрбір қарыз алушының әрбір ковенанты бойынша** AI агенті төмендегі ақпаратты анықтауы тиіс:

1. **`status`** — `COMPLIANT` (сақталған) немесе `BREACH` (бұзылған).
2. **`actual`** — ковенант шектейтін көрсеткіштің нақты мәні.
3. **`evidence_txn_id`** — егер бұзушылық белгілі бір транзакциямен байланысты болса, сол транзакцияның ID.

| Файл / бума | Сипаттамасы |
|------|---------|

Құжаттың қай қарыз алушыға тиесілі екенін тек оның мазмұнымен танысқаннан кейін ғана анықтауға болады. |
| `submission_template.json` | Жауап берілуі тиіс барлық сценарийлер мен ковенанттардың алдын ала дайындалған тізімі. Барлық өрістер бос күйде берілген. **Оларды толтырып жіберіңіз.** |

## 3. Тапсырылатын нәтиже

Сіз `submission_template.json` құрылымына **толық сәйкес келетін** `submission.json` атты **бір JSON файлын** жіберуіңіз қажет. Құрылымы келесідей:

- алдымен қарыз алушының `scenario_id` мәні;
- кейін ковенанттың **тармақ нөмірі**;
- содан соң сәйкес жауап ұяшықтары.

```json
{
  "team": "your-team-name",
  "contact_email": "you@example.com",
  "model": "claude-sonnet-5",
  "answers": {
    "T1": {
      "6.1": { "status": "COMPLIANT", "actual": 1850000.00, "evidence_txn_id": null },
      "6.2": { "status": "BREACH",    "actual": 5400000.00, "evidence_txn_id": null },
      "6.3": { "status": "BREACH",    "actual": 300000.00,  "evidence_txn_id": "TXN-T1-0020" }
    },
    "T2": {
      "6.1": { "status": "BREACH",    "actual": 450000.00,  "evidence_txn_id": "TXN-T2-0001" },
      "6.2": { "status": "COMPLIANT", "actual": 3.00,       "evidence_txn_id": null },
      "6.3": { "status": "COMPLIANT", "actual": 3500000.00, "evidence_txn_id": null }
    }
  }
}
```

**Үлгіде барлық қажетті ұяшықтар алдын ала дайындалған.** Жаңа кілттер құрудың қажеті жоқ — әрбір дайын ұяшықтағы үш бос мәнді ғана толтырасыз. Сіздің **жалғыз міндетіңіз** — оқылған ковенанттың қай ұяшыққа сәйкес келетінін дұрыс анықтау.

### Қажетті ұяшықты қалай табуға болады

**Ковенантты анықтау** оңай: ұяшықтар несие шартындағы ковенант орналасқан **тармақ нөмірімен** белгіленген. Мысалы, шарттың 6.2-тармағы JSON файлындағы `"6.2"` ұяшығына сәйкес келеді.

**Қарыз алушыны анықтау** үшін қосымша бір қадам қажет. Құжаттарда қарыз алушы компания атауы және `account_id` арқылы көрсетіледі, ал үлгі файлында — `scenario_id` арқылы.

Бұл екі идентификаторды байланыстыратын негізгі дереккөз — транзакциялар тізілімі. **Әрбір транзакция идентификаторы (`txn_id`) сол транзакция тиесілі қарыз алушының `scenario_id` мәнінен басталады:**

| Тізілім жазбасы | |
|---|---|
| `txn_id` = `TXN-P1-0039` | `scenario_id` — **`P1`** |
| `account_id` = `ACC-7801` | Қарыз алушының шот идентификаторы |

Демек, егер құжатта `ACC-7801` көрсетілсе, онда ол жауаптары `"P1"` кілтінің астында орналасқан қарыз алушыға тиесілі болады.

Әрбір `account_id` тек **бір ғана** `scenario_id` мәніне сәйкес келеді.

### Өрістерді толтыру қағидалары

| Өріс | Не көрсету қажет |
|---|---|
| `status` | Тек `"COMPLIANT"` немесе `"BREACH"` мәндерінің бірі. Барлық әріптер бас әріппен жазылуы тиіс. |
| `actual` | **Оң таңбалы**, үтірден кейін **екі таңбаға дейінгі** сандық мән. Ақшалай көрсеткіштер — АҚШ долларымен, коэффициенттер — кәдімгі сан ретінде беріледі. |
| `evidence_txn_id` | Нәтижені **айқындайтын** жалғыз транзакцияның идентификаторы немесе `null`. Коэффициенттік және агрегаттық тексерулер үшін бұл өріс әдетте `null` болады және кез келген мән қабылданады. |

#### `actual` дегеніміз не

**Ковенант шектейтін көрсеткіштің нақты мәні.** Егер тармақ X көрсеткішін $300,000 сомасымен
шектесе, `actual` — сол X: ковенант сақталғанда лимиттен төмен, бұзылғанда лимиттен жоғары.
Екі жағдайда да көрсетіңіз.

- Әрқашан **оң таңбалы** сан, шығыстар үшін де. Тізілімде шығыстар теріс сомамен берілген;
  `actual` — сол соманың абсолюттік мәні. Ақшалай көрсеткіштер — АҚШ долларымен, коэффициенттер —
  кәдімгі сан ретінде (`1.68`, `1.68x` емес).
- Кейбір ковенанттар ескертпе орындалған жағдайда лимиттен асуға жол береді немесе тек шарт
  іске қосылғанда ғана қолданылады. Мұндай жағдайда да `actual` — көрсеткіштің нақты мәні:
  `status` `COMPLIANT` болса да, ол лимиттен жоғары бола алады. Дәл сол мәнді көрсетіңіз —
  шарттың өз мәнін емес және `null` емес.

#### Не дәлел болып саналады

`evidence_txn_id` — бұл **нәтижені айқындайтын жалғыз транзакция**: қайта жіктелуі, есепке
қосылуы, есептен шығарылуы немесе түзетілуі ковенанттың бұзылуына әкелетін транзакция. Оны алып
тастасаңыз, вердикт өзгереді.

Жалпы сомаға үлес қосатын транзакция дәлел болып **саналмайды**: тексерілетін санаттағы ең ірі жол
да, кезең жабылар алдындағы соңғы жол да, жинақталған соманы кездейсоқ шектен шығарған жол да
дәлел емес.

Нәтиже жалғыз транзакциямен айқындалмайтын жерде — коэффициенттік тексерулер, агрегаттық
шектеулер — кілтте `null` тұрады. Мұндай ұяшықтарда көрсететін транзакция жоқ, сондықтан жіберілген
мән ескерілмейді — `null` да. **Бұл 0.20 автоматты түрде берілмейді, еңбекпен алынады: ол `actual`
мәнімен бірге сол шкала бойынша кемиді.** Дәл мән 0.20-ның барлығын сақтайды, 2.5% қателік —
жартысын, 5% қателік (сондай-ақ жоқ немесе сан емес `actual`) — ештеңе қалдырмайды. Сондықтан
мұндай ұяшықтарда транзакция идентификаторын болжаудың қажеті жоқ: дұрыс сан ғана ұпай әкеледі.

Кілттердің атауын **өзгертпеңіз**, жаңасын **қоспаңыз** және барларын **жоймаңыз**. Толтырылмаған кез келген ұяшық бағаланбайды.

Жіберілетін файл **үлгі құрылымына толық сәйкес келетін, дұрыс құрылымдалған JSON пішіміндегі жарамды файл** болуы тиіс. JSON құрылымы бұзылған немесе мәндердің типтері дұрыс көрсетілмеген жағдайда, тиісті ұяшықтар бағаланбайды.

Сонымен қатар жоғарғы деңгейдегі келесі өрістерді міндетті түрде толтырыңыз:

- `team`
- `contact_email`
- `model`

## 4. Бағалау

Әрбір ковенант — бір **ұяшық**. Әрбір ұяшық 0-ден 1-ге дейін бағаланады, содан кейін
ұяшықтарға қорытынды нәтижеде **күрделілігі бойынша салмақ беріледі**.

| Өріс | Ұпай | Не үшін беріледі |
|---|---|---|
| `status` | **0.50** | Кілтпен дәл сәйкес келетін `"COMPLIANT"` немесе `"BREACH"`. |
| `actual` | **0.30** | «Дұрыс/қате» емес, кемімелі шкаламен бағаланады — төменде қараңыз. |
| `evidence_txn_id` | **0.20** | Кілтте көрсетілген дәл сол `txn_id`. Кілтте `null` тұрса, бұл ұпай `actual` мәнімен бірге сол шкала бойынша кемиді — төменде қараңыз. |

**`actual` «бәрі не ештеңе» қағидасымен емес, шкаламен бағаланады.** Дәл сәйкестік толық
0.30 береді; одан әрі ұпай **салыстырмалы** қателікке қарай сызықты кемиді және 5%-да
нөлге айналады:

```
ұпай = 0.30 × max(0, 1 − e / 0.05)        e = |сіздің мәніңіз − кілт| / |кілт|
```

Яғни дөңгелектеу қателігі дерлік ештеңе тұрмайды, 2.5% қателік жартысын береді, ал 5%
қателік — нөл. `actual` мәнін үтірден кейін екі таңбамен көрсетіңіз, мыңдыққа дейін
дөңгелектемеңіз.

| Жағдай | Нәтиже |
|---|---|
| `status` қате | Қалған өрістер қаншалықты дәл болса да, **бүкіл ұяшық — 0**. |
| Ұяшық жоқ, атауы өзгертілген немесе жаңасы қосылған | Сол ұяшық үшін **0**. |
| `status` дәл `COMPLIANT` / `BREACH` емес | Сол ұяшық үшін **0**. |
| `actual` жоқ, сан емес немесе 5% және одан көп ауытқыған | 0.30 жоғалады, **сондай-ақ** кілтте дәлел `null` болса, 0.20 да жоғалады. |
| `actual` ішінара ауытқыған | Кілтте дәлел `null` болса, 0.30 да, **0.20 да** сонымен бірге кемиді. |
| JSON құрылымы бұзылған | Тиісті ұяшықтар бағаланбайды, ал бағаланбайтын ұяшық — **0**. |

Бос ұяшық пен қате ұяшық бірдей бағаланады, сондықтан барлық ұяшықты толтырыңыз.

## Жауапкершіліктен бас тарту

**Осы деректер жиынтығындағы барлық мәліметтер ойдан шығарылған.** Қарыз алушылар, контрагенттер,
аудиторлар, еншілес ұйымдар, кредиттік шарттар, KYC досьелері, аудиторлық есептер және олардағы
барлық сандық мәндер осы конкурс үшін арнайы жасалған. Аталған компаниялар жоқ, мұндағы бірде-бір
шарт нақты шарт болып табылмайды және операциялардың ешқайсысы жасалмаған. Нақты ұйымдармен,
тұлғалармен немесе мәмілелермен кез келген ұқсастық — кездейсоқтық.

Нақты өмірде бар ұйымның атауы кездескен жағдайда, ол тек ойдан шығарылған жағдай ретінде ғана
қолданылған. **Бұл жиынтықтағы бірде-бір құжат Halyk Bank of Kazakhstan JSC немесе кез келген
өзге ұйымның нақты клиентін, шартын, операциясын не кредиттік шешімін білдірмейді.**

Материалдар қаржылық, заңдық, аудиторлық немесе бухгалтерлік кеңес болып табылмайды және
олардағы ешбір мәлімет қандай да бір нақты ұйым туралы дерек ретінде пайдаланылмауы тиіс.
