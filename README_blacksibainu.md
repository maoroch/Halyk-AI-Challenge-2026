# blacksibainu — подход к решению

## Пайплайн (`pipeline/`)

1. `extract_text.py` — извлечение текста из всех PDF в `documents/` (pdfplumber) → `cache/text/`.
2. `classify_docs.py` — детерминированная классификация каждого документа по текстовым маркерам:
   `credit_agreement` (действующий договор), `superseded_credit_agreement` (устаревшая редакция —
   исключается), `kyc_dossier_authoritative` (авторитетное KYC-досье со списком связанных сторон),
   `audit_notes` / `aup_report_final` / `treasury_memo` (финальные источники реклассификаций и
   исправлений), `draft_interim_EXCLUDE` (черновики аудита — явно помечены как не финальные,
   исключаются), плюс несколько категорий подтверждённого шума (Atlas-проект, HR-чеклисты,
   протоколы советов директоров, страховки и т.д. — не относятся к ковенантам).
3. `match_scenario_docs.py` — сопоставление документов со сценариями по `account_id` **и** точному
   названию компании-заёмщика (важно: есть похожие названия вида «Shymkent Refinery JSC» vs
   «Shymkent Refinery **Services** JSC» — разные сценарии).
4. `build_bundles.py` — сборка на сценарий: текст статьи 6 договора (регексом, без остального
   договора — экономит токены), + авторитетные вспомогательные документы + таблица транзакций
   заёмщика из `master_ledger_2025.csv`.
5. `compute_covenants.py` — один вызов LLM на сценарий (все 3 пункта 6.1–6.3 сразу), возвращает
   `status` / `actual` / `evidence_txn_id` строго по JSON-схеме.
6. `assemble_submission.py` — сборка `submission.json` из `submission_template.json` (top-level
   `team`/`contact_email`/`model` + округление `actual` до 2 знаков, `abs()`, отбрасывание
   `evidence_txn_id`, которого нет в реестре — защита от галлюцинаций).

## Ключевые находки по датасету (ловушки)

- В каждом сценарии — **две** версии кредитного договора: действующая и явно помеченная
  `НЕДЕЙСТВУЮЩАЯ РЕДАКЦИЯ` (другие числа по ковенантам!). Нужно брать только действующую.
- Есть черновые «промежуточные ведомости» аудита, которые сами говорят «не окончательная позиция,
  руководствуйтесь только финальным отчётом» — предлагаемая в них реклассификация может быть НЕ
  принята в финальном отчёте (пример: B1/Ekibastuz Energy — предложенная в драфте реклассификация
  TXN-B1-0023 не попала в финальный AUP-отчёт, там фигурирует совсем другая транзакция).
- Связанные стороны определяются строго по доле участия в KYC-досье (обычно порог ≥20%) — контрагент
  чуть ниже порога не считается связанной стороной, даже если явно упомянут рядом.
- Транзакции содержат смешанные валюты (USD/EUR) без указания курса конвертации — при расчёте
  долларовых показателей EUR-строки нужно исключать.
- Названия контрагентов могут вводить в заблуждение (например, «...Payroll Ltd» с описанием
  операции «Interest payment» — это НЕ зарплата).

## Известное ограничение — ТРЕБУЕТ ДОРАБОТКИ

Сверка с `ground_truth.json` (эталонные ответы, включены в архив этой публичной версии кейса)
показала точность `status` **~47%** (17/36 ячеек) при текущей схеме «1 вызов LLM на весь сценарий
сразу с 3 пунктами + ~56 транзакциями». Похоже, модель не справляется с классификацией всех
транзакций за один проход при таком объёме контекста и инструкций.

**Следующий шаг, если будет время:** разбить `compute_covenants.py` на отдельный вызов LLM на
каждый пункт ковенанта (36 вызовов вместо 12) — должно дать модели больше «внимания» на одну
конкретную классификационную задачу за раз.

## Модели

- Основная: `llama-3.3-70b-versatile` через Groq API (бесплатный тариф, TPM=12000, TPD=100000/ключ
  — при большом числе вызовов может понадобиться несколько ключей, см. `GROQ_API_KEYS` в `.env`).
- Резервная (не рекомендуется для этой задачи — не справилась с объёмом контекста): локальная
  `qwen2.5:7b-instruct` через Ollama, `ollama_client.py`.

## Запуск

```bash
cp .env.example .env   # впишите свои GROQ_API_KEYS (через запятую, для ротации при лимитах)
pip install -r requirements.txt
python pipeline/extract_text.py
python pipeline/classify_docs.py
python pipeline/match_scenario_docs.py
python pipeline/build_bundles.py
python pipeline/compute_covenants.py
python pipeline/assemble_submission.py
```
